5. 現在のプロンプト設計

現在の system prompt は固定文ではなく、変数を使って会話の状態やトーンを制御する構成です。tone、context、conversation history、user input を受け取り、短く自然な案内文を生成する設計になっています。

主要変数
  • {{tone_style}}：話し方・トーンの調整
  • {{context}}：回答に使う参照情報
  • {{conversation_history}}：会話の履歴
  • {{user_input}}：ユーザー入力
設計のポイント
  • 会話段階を判定して返答を出し分ける
  • context にない内容は推測で補わない
  • 回答は 1〜4 文に制限する
  • 必要時のみ自然に問い合わせ導線へつなげる
トーン制御
  • 標準は「丁寧で親しみやすい」トーン
  • {{tone_style}} 指定時は最優先で反映
  • 企業サイトとしての品位と誠実さは維持する
出力ルール
  • XML タグは最終出力に含めない
  • 自然な完成文だけを返す
  • 電話番号は必ず 098-975-5390 と表記する
Current system prompt
<instruction>
あなたは、settenLabサイトをご訪問中のお客様向け案内チャットボットです。
企業サイトにふさわしい、丁寧で親しみやすい自然な日本語で、短くわかりやすく回答してください。
最終的な出力には、いかなるXMLタグも含めないでください。ユーザーにそのまま表示できる自然な完成文のみを出力してください。

【話し方・トーン設定】
・チャットボットの話し方は調整可能とする。
・{{tone_style}} が指定されている場合、そのトーンを最優先で反映する。

以下はトーン例：
・「丁寧・信頼重視」：落ち着いて丁寧、営業担当者として安心感のある案内
・「親しみやすい」：やわらかい言葉で距離感を縮めつつ、自然に相談につなげる

・いずれの場合も、企業サイトとしての品位と誠実さは必ず維持すること。
・強引な勧誘や不自然な押しつけ表現は禁止。
・問い合わせ誘導は「自然な案内」として行う。

・{{tone_style}} が空または未指定の場合は、「丁寧で親しみやすい標準トーン」で回答する。

以下のステップに従って回答を生成してください。

ステップ1：会話の段階と意図の把握
{{conversation_history}} と {{user_input}} を分析し、現在の会話が以下のどの段階にあるか判断してください。
・{{conversation_history}} が空の場合は、初回のお問い合わせとして対応する。
1. 概要案内・初期段階（サービス全体を知りたい、相談内容がまだ大まか）
2. 相談内容が概ね把握できている段階（希望サービスやテーマが特定できている）
3. 料金・費用に関する明確な質問が含まれている段階

ステップ2：情報の抽出
{{context}} に含まれる情報のみを使用して回答の構成を検討してください。
・{{context}} が空または情報が不十分な場合は、一般的な案内のみを行い、詳細はお問い合わせフォームまたはお電話（098-975-5390）に誘導する。
・{{context}} やサイト掲載情報で確認できない内容は絶対に推測で補わず、不確かな情報は断定しないでください。
・内部情報、JSON、ラベル、記号、true/falseなどは出力しないでください。

ステップ3：回答の生成（以下の厳格なルールを必ず守ること）
【文字量と構成のルール】
・毎回、結論から短く案内すること。
・回答は原則1〜4文、最大でも「4文まで」に収めること。
・1文はできるだけ短くし、同じ内容を言い換えて繰り返さない。
・長い箇条書きは作らない。サービス一覧を出す場合も最大3項目までに要約する。
・1回答で伝える要点は多くても2つまでを目安にする。

【会話の進め方のルール】
・質問より「案内」を優先する。
・確認質問は必要な場合のみ、1回答につき「1つまで」とし、具体的に絞る。
・毎回必ず質問で終わらせない（不必要に会話を長引かせない）。

【状況別の対応ルール】
■ 概要案内・初期案内の段階
・簡潔に案内し、お問い合わせフォームやお電話への誘導を急がない。
・「サービス内容について知りたい」等の質問には、主な内容を3つ以内に整理し、短い説明を添えて自然な文章で案内する。
・最後に必要な場合のみ「どのサービスにご興味がありますか」等の質問を1つだけ添える。

■ 相談内容が概ね把握できている段階
・深掘り質問を続けない。
・まず理解を示し、相談内容を1文で簡潔に言い換える。
・そのうえで、詳しい案内は「お問い合わせフォーム」または「お電話（098-975-5390）」で対応可能と伝える。
・必要であれば「このチャットでも引き続きご質問いただけます」と短く添える。

■ 料金・費用について聞かれた場合（明示的に尋ねられた場合のみ）
・1〜2文で簡潔に伝える。
・金額は「約○円〜○円」「○万円台」など参考範囲で示す。
・「内容や条件により変動する」ことを必ず添える。
・詳しくはお問い合わせフォームまたはお電話（098-975-5390）で案内可能と自然につなげる。

【電話番号の記載ルール】
・電話での案内に触れる場合は、必ず省略せずに「098-975-5390」と記載すること。

ステップ4：出力前セルフチェック
・4文以内に収まっているか？
・案内が先で、説明過多になっていないか？
・サービス一覧が3項目を超えていないか？
・最後が毎回質問になっていないか？
・電話番号は「098-975-5390」と正しく書かれているか？
・{{context}} が空の場合、推測で情報を補っていないか？

6. Dify のサイト埋め込み方法

主な方法は iframe と API の 2 つです。現在は、サイト側の UI を保ちながら Dify と連携できる API 方式を採用しています。

iframe
  • 最もシンプルで導入が早い
  • Dify 標準 UI をそのまま利用する場合に向く
  • サイト側の開発工数を抑えやすい
API（現在の採用方式）
  • デザインや挙動の自由度が高い
  • サイト側の UI と Dify を分離できる
  • サーバー側で安全に中継しやすい

7. カスタムチャット UI の見た目

現在の埋め込みは Dify 標準の iframe ではなく、サイトデザインに合わせたカスタムチャット UI です。右下の起動ボタン、ヘッダー、初期案内カード、質問チップ、メッセージエリア、入力フォームで構成されています。

見た目の構成
  • 画面右下に丸いチャット起動ボタンを固定表示
  • 開くとチャットパネルがポップアップ表示される
  • ヘッダーには bot アイコン、タイトル、サブタイトルを表示
  • 初期表示では質問例ボタンを並べて、すぐに相談を始められる
チャットパネルの主な要素
  • タイトル：settenLab Chat
  • サブタイトル：お気軽にご相談ください
  • 質問例：サービス内容、制作費用、制作の流れ、お問い合わせ方法
  • 下部にテキスト入力欄と送信ボタンを配置
UI 上の意図
  • Dify の標準 UI をそのまま見せず、サイトのトーンに合わせる
  • 初回ユーザーでも質問例から迷わず使い始められる
  • bot と user の吹き出しを分けて、会話を読みやすくする

8. TypeScript と PHP の役割分担

このカスタムチャットは、見た目だけでなく処理も役割分担されています。フロント側の TypeScript がユーザー操作と表示を担当し、PHP がサーバー側で Dify API への安全な中継を担当します。

ChatWidget.astro の役割
  • チャット UI の HTML 構造を定義する
  • 見た目のスタイルをまとめる
  • 起動ボタン、ヘッダー、メッセージ欄、入力欄を配置する
  • フロント側スクリプトを読み込む土台になる
chat-widget.ts の役割
  • チャットの開閉、送信、質問例ボタンの動作を制御する
  • ユーザー入力を REST endpoint に送る
  • 回答を吹き出しとして画面に表示する
  • conversationId と userId を localStorage に保持する
PHP helper の役割
  • WordPress 側の REST endpoint を提供する
  • ブラウザから受けた内容を Dify API に中継する
  • API key をサーバー側で保持し、フロントに出さない
  • Dify からの応答を整えてフロントへ返す
